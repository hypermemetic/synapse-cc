# synapse.lock and Content-Stable File Hashes

**Date**: 2026-03-11
**Components**: synapse-cc (Haskell), hub-codegen (Rust)

---

## Problem

Before this work, two things were broken:

**1. Build state was invisible to the team.**
All generated file hashes lived in `~/.cache` on the developer's machine. A second
developer — or a CI runner — had no baseline. On first build they'd see every file
as "new" and write everything, even if nothing had changed.

**2. Adding a new plugin changed files that had nothing to do with it.**
When you registered `spin` in fidget-spinner and rebuilt, four files got new hashes:

```
fidget/client.ts        ← real change  (spin() method added)
types.ts                ← SPURIOUS    (only the header comment changed)
package.json            ← SPURIOUS    (only the version string changed)
.codegen-metadata.json  ← SPURIOUS    (timestamp + IR hash in the body)
```

`types.ts` had identical TypeScript content line-for-line. The IR hash
(`Plexus Hash: abc123...`) and a timestamp had been stamped into its header comment,
so every IR change touched every file that carried the header.

---

## Solution

Two independent fixes, both in the same direction: **push identifying information
out of file content and into the lock file**.

---

## Part 1: synapse.lock

### What it is

A JSON file written to the project root after every successful build, committed to git.

```
your-project/
  synapse.config.json   ← you write this
  synapse.lock          ← synapse-cc writes this, you commit it
  src/lib/plexus/       ← generated client lives here
```

### What it stores

```json
{
    "version": "1",
    "synapseCC": "0.2.0",
    "hubCodegen": "0.2.0",
    "updatedAt": "2026-03-11T21:19:08Z",
    "targets": {
        "src/lib/plexus": {
            "backend": "fidget-spinner",
            "irHash": "6b2b05454e418aa6",
            "transport": "ws",
            "files": {
                "fidget/client.ts": "4b999cc3e956fbb8",
                "rpc.ts":           "e9fd65874333ae25",
                "transport.ts":     "8a506aa098fe4ea2",
                "types.ts":         "17742b2b719f7cd3",
                ...
            }
        }
    }
}
```

Keyed by **outputDir** (always present in config). One lock entry per build target.
Multi-target configs produce multiple entries in the same file.

### Priority

```
synapse.lock  (project — committed, shared)
     ↓  takes priority
~/.cache      (machine — per-developer, not committed)
```

On a machine with no `~/.cache` (CI, new developer), the lock provides the file
hashes for three-way merge. Files the generator would produce identically are
not rewritten.

### Three-way merge recap

The merge compares three versions of each file:

```
cached hash   current hash on disk   new hash from generator   → decision
─────────────────────────────────────────────────────────────────────────────
  (none)          (none)                   any                  → write (new)
  H               (none)                   any                  → write (restore)
  (none)           H                        H                   → skip (unchanged)
  H == H           H                        H                   → skip (unchanged)
  H == H           H                       H2                   → write (safe update)
  H1              H2 ≠ H1                   any                  → SKIP (user modified)
```

"Cached hash" now comes from `synapse.lock` first, `~/.cache` second.

## Part 2: Content-Stable Hashes

### Root cause

hub-codegen was embedding IR-level metadata into generated file content:

| File | What changed | Why it changed |
|------|-------------|----------------|
| `types.ts` header | `Generated: <timestamp>` + `Plexus Hash: <ir_hash>` | Every build, even identical output |
| `package.json` | `"version": "0.0.0-{ir_hash}"` | Any change anywhere in the IR |
| `.codegen-metadata.json` | `timestamp` + `plexus_hash` fields | Same as above |

The IR hash is a hash of the entire backend schema. It changes when *any* plugin
changes — including ones unrelated to your target files.

### Fix

Remove IR hashes and timestamps from generated file content:

**`types.ts` header** — before:
```typescript
/**
 * Auto-generated by hub-codegen toolchain
 * DO NOT EDIT MANUALLY
 *
 * Generated: 2026-03-11T21:25:38Z        ← removed
 * Toolchain:
 *   - synapse-cc v0.2.0
 *   - hub-codegen v0.2.0
 *
 * Backend: fidget-spinner
 * Plexus Hash: 1b8ddd85d53d2009           ← removed
 */
```

**`types.ts` header** — after:
```typescript
/**
 * Auto-generated by hub-codegen toolchain
 * DO NOT EDIT MANUALLY
 *
 * Toolchain:
 *   - synapse-cc v0.2.0
 *   - hub-codegen v0.2.0
 *
 * Backend: fidget-spinner
 */
```

**`package.json` version** — before:
```
"version": "0.0.0-{ir_hash[..16]}"        ← changes whenever any plugin changes
```

**`package.json` version** — after (two-pass generation):
```
"version": "0.0.0-{content_hash}"         ← hash of generated code files only
```

The content hash is computed from all generated `.ts` files *before* `package.json`
is generated. It changes iff the generated client code changes.

**`.codegen-metadata.json`** — `timestamp` and `plexus_hash` fields removed.
`file_hashes` (the useful part) is preserved.

### Result

Adding `spin` to fidget-spinner now produces exactly this diff:

```
fidget/client.ts         ← spin() method added
package.json             ← version updated (code changed)
.codegen-metadata.json   ← file_hashes entry updated
```

```
types.ts                 ← no change  ✓
rpc.ts                   ← no change  ✓
transport.ts             ← no change  ✓
index.ts                 ← no change  ✓
```

## irHash and the cache limitation

`synapse.lock` records the `irHash` per target. This enables a future optimisation:
before running the full pipeline, compare the live backend hash against the lock's
`irHash`. If they match, the schema hasn't changed and we can skip even the schema
fetch.

Currently, `Cache.validateCache` checks toolchain versions and plugin schema hashes
stored in `~/.cache`. It does not yet compare against `synapse.lock`'s `irHash`.
This means schema changes from dynamic backends (like fidget-spinner's register/
unregister) require `--force` to bypass the version-based cache hit.

The fix is straightforward: in `getCachedFileHashes`, if a lock entry exists,
fetch the live IR hash and compare it against `lt.ltIrHash`. If different, treat
as a cache miss.

## Hash algorithm

SHA-256 of the UTF-8 file content, first 16 hex characters. Identical algorithm in
both hub-codegen (`src/hash.rs`) and synapse-cc (`SynapseCC/Merge.hs`).

```
computeFileHash :: Text -> Text
computeFileHash = T.take 16 . decodeUtf8 . Base16.encode . SHA256.hash . encodeUtf8
```

```rust
pub fn compute_file_hash(content: &str) -> String {
    format!("{:x}", Sha256::digest(content.as_bytes()))[..16].to_string()
}
```
