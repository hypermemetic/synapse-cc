# Leaf Activation Schema Fetch Failure

**Status**: Resolved (workaround documented)
**Date**: 2026-03-13
**Components**: synapse-cc (Haskell), plexus-core (Rust), plexus-macros (Rust)

---

## Problem: Internal Error When Fetching Schema for Leaf Activations

synapse-cc fails with `RpcErrorObj {errCode = -32603, errMessage = "Internal error"}` when generating a client for a backend that has a leaf activation registered via `.register()`.

The error occurs during IR generation when synapse recursively walks the schema tree and attempts to fetch the schema for each child plugin.

---

## Error Reproduction

```
synapse-cc typescript monochrome -P 4448 -o ./generated --transport browser

==> Generating IR...
[!] Error: synapse failed (exit code 1)

Output:
synapse: Schema fetch failed: NavError (FetchError "Protocol error: Subscription error:
  RpcErrorObj {errCode = -32603, errMessage = \"Internal error\", errData = Nothing}"
  ["monochrome","monochrome"])
```

The path `["monochrome","monochrome"]` indicates synapse is navigating from the root `monochrome` DynamicHub into a child also named `monochrome`.

---

## Root Cause

Two registration methods exist in `DynamicHub`:

| Method | What it does | Schema routing |
|--------|-------------|----------------|
| `.register(activation)` | Registers methods + adds to `activations` map | NOT added to `child_routers` |
| `.register_hub(activation)` | Same + adds to `child_routers` map | Added to `child_routers` |

When DynamicHub builds its root schema via `plugin_children()`, it lists ALL registered activations (both leaf and hub) as children. Synapse sees these children and recursively tries to fetch each child's schema by navigating to `<root>.<child>.schema`.

For hub activations (registered via `.register_hub()`), the `child_routers` map has an entry, so the DynamicHub can route the schema request to the child's `ChildRouter` implementation. This works.

For leaf activations (registered via `.register()`), the `child_routers` map has NO entry. The DynamicHub cannot route the schema request, and returns an internal error.

```
DynamicHub.plugin_children()
  → lists [player, monochrome]     // Both appear as children

synapse walks children:
  → monochrome.player.schema       // ✅ player is in child_routers (register_hub)
  → monochrome.monochrome.schema   // ❌ monochrome is NOT in child_routers (register)
                                   //    → Internal error (-32603)
```

---

## The Mismatch

The contract violation is:

1. `plugin_children()` advertises ALL activations as navigable children
2. But only `register_hub()` activations are actually routable via `child_routers`
3. Synapse trusts `plugin_children()` and tries to navigate to all of them

This means **any backend with a leaf activation will break synapse-cc**.

---

## Workaround: Convert Leaf to Empty Hub

The activation must implement `ChildRouter` and use the `hub` flag in the macro, even if it has no children:

### 1. Add `hub` flag to the macro

```rust
#[plexus_macros::hub_methods(
    namespace = "monochrome",
    version = "0.2.0",
    hub,  // ← Required for schema routing
    description = "...",
    crate_path = "plexus_core"
)]
impl MonoHub { ... }
```

### 2. Add empty `plugin_children()`

```rust
pub fn plugin_children(&self) -> Vec<ChildSummary> {
    vec![]  // No children, but method must exist for hub macro
}
```

### 3. Implement `ChildRouter` (after the macro impl block)

```rust
#[async_trait]
impl ChildRouter for MonoHub {
    fn router_namespace(&self) -> &str { "monochrome" }

    async fn router_call(
        &self, method: &str, params: Value,
    ) -> Result<PlexusStream, PlexusError> {
        // self.call() is generated by the hub_methods macro
        Activation::call(self, method, params).await
    }

    async fn get_child(&self, _name: &str) -> Option<Box<dyn ChildRouter>> {
        None  // No children
    }
}
```

**Important**: The `ChildRouter` impl must appear AFTER the `#[hub_methods]` impl block, because `self.call()` is generated by the macro.

### 4. Change registration

```rust
DynamicHub::new("monochrome")
    .register_hub(mono_hub)    // was: .register(mono_hub)
    .register_hub(player_hub)
```

---

## Proper Fix (plexus-core)

The root cause should be fixed in plexus-core, not worked around per-activation. Two options:

### Option A: Don't list leaf activations as children

`DynamicHub::plugin_children()` should only list activations that are in `child_routers`. Leaf activations would still have their methods registered but wouldn't appear in the schema tree as navigable children.

### Option B: Make leaf activations routable

`.register()` should also add activations to `child_routers` with an auto-generated minimal `ChildRouter` that supports schema fetching but returns no children. This would make the distinction between `.register()` and `.register_hub()` purely about whether the activation has its own children.

Option B is preferred — it preserves the current behavior where all activations appear in the schema tree, while fixing the routing gap.

## Comparison: Working vs Broken Configuration

| Aspect | Leaf (BROKEN) | Hub (WORKS) |
|--------|--------------|-------------|
| Macro flag | (none) | `hub` |
| Schema type | `PluginSchema::leaf(...)` | `PluginSchema::hub(...)` |
| `ChildRouter` impl | Not required | Required |
| `plugin_children()` | Not generated | Generated by macro |
| Registration | `.register()` | `.register_hub()` |
| In `child_routers` map | No | Yes |
| Recursive schema fetch | Fails (-32603) | Works |

## Affected Versions

- **plexus-core**: All versions with `DynamicHub`
- **synapse**: 3.5.0 (recursive schema walker)
- **synapse-cc**: All versions (delegates to synapse for IR)
