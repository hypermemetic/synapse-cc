# UX-10: Fix Cache Hit Behavior

blocked_by: []
unlocks: []

## Problem

Three cache correctness issues:

### 1. FullCacheHit doesn't verify output exists
```haskell
FullCacheHit -> do
  -- TODO: Copy cached code to output directory if needed
  let outputPath = optOutput (cfgOptions config)
  pure $ Right $ CompiledPath outputPath
```
If the user deleted `./generated/` and reruns, synapse-cc reports success pointing at nothing.

### 2. Hardcoded tool versions
```haskell
tvSynapse irToolchain /= "0.2.0.0"  -- TODO: Get from synapse somehow
tvHubCodegen codeToolchain /= Just "0.1.0"  -- TODO: Get from hub-codegen
```
Cache never invalidates on tool version changes.

### 3. PartialCacheHit falls through to full regen
The V2 granular validation logic is fully implemented but the result is discarded — it always does a full regeneration.

## Scope

### 1. Verify output directory on cache hit
On `FullCacheHit`, check that the output directory exists and contains files. If not, fall through to `CacheMiss`.

### 2. Dynamic tool version detection
At discovery time, run `synapse --version` and `hub-codegen --version`, store results in `ToolLocations`. Use these real versions in cache validation and manifest writing.

### 3. Wire up partial regeneration (stretch)
This is a larger effort. At minimum, log that partial regen is not yet supported and explain why a full regen is happening:
```
[i] 2 of 12 plugins changed — full regeneration (partial regen not yet supported)
```

## Acceptance Criteria

- Cache hit with missing output dir triggers regeneration
- Tool versions in cache manifests match installed versions
- (Stretch) Partial cache hit logs which plugins changed
